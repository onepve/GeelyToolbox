# 发布更新说明 (changelog) 手写覆盖目录

发版时车机更新弹窗显示的更新说明**不再由发布脚本硬编码**，而是按以下优先级生成：

1. **本目录下的手写文件**：`docs/changelog/<tag>.txt`（如 `beta-v1.7.33.3.txt`）—— 首选，用于精炼过的正式文案；
2. **版本控制真实提交**：上一个 Tag 到本次 Tag 之间的提交主题，自动剥离 `feat:` / `fix:` 等英文前缀并加序号。

没有第三种降级：**绝不回落到硬编码的历史文案**（历史缺陷：测试通道曾写死远古版本号，导致每次发版都带出过期更新内容）。

## 只保留两份（正式版 + 在测测试版）

本目录**不是历史归档**，任何时刻最多只放三样东西：

| 文件 | 说明 |
|---|---|
| `README.md` | 本说明 |
| `vX.Y.Z.txt` | **当前最新正式版**的手写说明，随正式版发版被覆盖刷新 |
| `beta-vX.Y.Z.N.txt` | **当前在测测试版**的手写说明，下一次打 Tag 时改名/覆盖 |

- 旧版本的说明**发完即可删**：车机弹窗读的是当时那一次生成的 `version.json` / `version-beta.json`，历史 txt 留在仓库只会让人误以为还有旧版在架。
- 不要在这里放截图、日志包、对比表——它们属于交付附件，不属于发版文案。
- 删旧文件属文档整理，不影响任何 Tag 的 Release 正文（正文在打 Tag 时已固化到 R2 元数据里）。

## 手写文件格式

- 纯文本，每行一条改动，**不要自己写序号**（构建器统一编号）；
- 以 `#` 开头的行是注释，会被忽略；
- 空行会被忽略；
- 不要写【测试通道优先体验 ...】这类标题行，构建器按 Tag 自动生成，避免版本号写错。

示例 `docs/changelog/beta-v1.7.33.3.txt`：

```
修复更新说明错位：改为按真实改动生成，不再显示过期内容
```

## 本地预览

```bash
# 查看某个 Tag 将生成的更新说明
python3 scripts/changelog_builder.py beta-v1.7.33.3

# 回归测试（含标题版本号一致性、覆盖优先级、前缀剥离等）
python3 scripts/test_changelog_builder.py
```
